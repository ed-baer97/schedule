# Продукт

Веб-сервис для составления и управления школьным расписанием: ручной и автоматический режимы, несколько школ на одной установке.

## Возможности

- Мультиарендность: платформенный админ создаёт школы и админов школ (логин/пароль в `/admin`)
- Вход по email/паролю (JWT в httpOnly cookie)
- Импорт из Excel: файл нагрузки на каждый предмет + файл кабинетов
- Справочники, нагрузка, назначения (в т.ч. подгруппы)
- Ручная сетка: drag & drop, смена кабинета по клику на урок (занятый — обмен с другим учителем), валидация конфликтов; непроставленные часы учителя — подсказка на сетке, день учителя в модалке добавления урока
- Автосоставление: «Заполнить день» — CP-SAT на один день смены (остаток часов, другие дни не трогает); режим «мягкий дозапол» сохраняет стоящие уроки и ставит только в свободные слоты; завуч запускает дни вручную по очереди; фильтр «не позже N-го урока» (например, без 7-х — их можно дозаполнить позже); опционально куски по параллелям (НШ 1–2→3–4, ОШ 5–6→7–9); время поиска на форме; сначала наполнение дня, затем soft-пакеты (сдвоенные, ранние уроки); «по учителю» — лесенка без полного DFS; Repair — residual-дозаполнение; фраза завуча (`POST /api/schedule/assist`) — в ползунки и локальные сдвиги после валидатора (Qwen только JSON-намерение, не выбирает `cell_id`); на стенде Celery + Redis
- Отчёты в Excel

## Сущности

| Сущность | Описание |
|----------|----------|
| Школа | Тенант: изолированные справочники и расписание |
| Пользователь | `platform_admin` или `school_admin` |
| Учителя | ФИО, контакты, закреплённый кабинет (хозяин комнаты) |
| Кабинеты | Номер, название, корпус, вместимость; несколько предметов (`subject_ids`), флаг «фиксированный» (`is_exclusive`), уровень (`school_level`: общий / НШ / ОШ), «только подгруппы» (`subgroup_only`) |
| Классы | Название (1А, 5Б), уровень (НШ/ОШ), смена, классный руководитель, кабинет класса |
| Предметы | Название, цвет; группа `natural_math` / `humanities` / `languages` / `practical` (естественно-математический, гуманитарный, языки, практические); флаг «нужен фиксированный кабинет» (пул комнат задаётся на кабинетах) |
| Назначения | предмет ↔ учитель ↔ класс, часы, подгруппа |
| Смены | уровень школы, сетка уроков, звонки; в день классного часа сетка может быть короче (`class_hour_lessons_count`) |
| Задачи (jobs) | фон автосоставления (Celery) |

## Правила

**Подгруппы.** Два учителя с часами на один предмет в одном классе → подгруппы. В одну ячейку несколько предметов — только если они в группах.

**Несколько предметов у учителя.** Один и тот же учитель в нескольких файлах нагрузки (разные предметы) — ведёт несколько предметов.

**Структура.** Начальная / основная школа → смены → классы. Учитель и кабинет конфликтуют по пересечению звонков; без звонков одинаковый номер урока не занимает другую смену.

**Настройки.** На школу и уровень: дни, максимум уроков по предмету в день, режим кабинетов (`class_room` — учитель приходит к классу, `teacher_room` — дети к учителю). Если в день два урока предмета — только подряд (как физкультура 1–2, не английский 5 и 7 с чужим предметом между ними). Один учитель в одном классе — не больше двух уроков **одного** предмета в день (3 математики нельзя; 2 математики + 1 информатика — можно). Ползунок «сдвоенные уроки рядом» (0–10): на 10 чётные часы только двойками (6 → 2–2–2), нечётные — максимум двоек плюс один одиночный. Для НШ — флаг «подгруппы уходят в кабинет учителя».

**Группы предметов.** На странице предметов: естественно-математический, гуманитарный, языки, практические (физкультура, технология, НВП, ОБЖ и подобные). Автосоставление штрафует, если разные предметы одной группы стоят подряд (математика сразу после физики). Сдвоенный урок одного предмета не штрафуется. Вес — ползунок «Предметы одной группы не подряд».

**Кабинеты и предметы.** Связь задаётся на странице кабинетов (несколько предметов на комнату: алгебра + геометрия + математика; история Казахстана + всемирная история + основы права). Страница предметов только показывает пул. Несколько кабинетов с одним предметом — пул (лаборатории информатики). Пустой список предметов = общий кабинет. Фиксированный кабинет (`is_exclusive`) обязан иметь хотя бы один предмет и принимает только их; пустой список снимает флаг. Предмет с «нужен фиксированный кабинет» ставится только в кабинеты своего пула. Нефиксированный предмет в не-exclusive кабинет (свой, общий или чужой предметный) — можно; авторасстановка ранжирует по стоимости: хозяин комнаты → тот же предмет (любой из списка) → общий → чужой нефиксированный. Авто (CP-SAT, лесенка, repair) всегда записывает конкретный кабинет: урок без комнаты не ставится; если свободной нет — час остаётся непроставленным (CP-SAT: ошибка INFEASIBLE). Сдвоенные уроки одного предмета в один день остаются в одном кабинете, если он свободен на оба часа; иначе каждый час берёт свободный кабинет из пула. В ручной сетке «Без кабинета» по-прежнему можно. Если включено «подгруппы НШ уходят», групповой урок (не фиксированный предмет) идёт в домашний кабинет учителя — только если кабинет разрешён предмету. В UI добавление предмета с флагом «фиксированный кабинет» само включает exclusive.

**Кабинеты начальной школы.** Тег `school_level` на кабинете — не то же самое, что exclusive. `NULL` = общий (спортзал, информатика, мастерские): доступен НШ и ОШ. `elementary` — только начальная: уроки основной школы сюда нельзя, даже если 1А на физкультуре и комната пустая. `secondary` — только основная. У НШ обычные уроки остаются в кабинете класса; исключения — предметы с «нужен фиксированный кабинет» (физкультура, труд, информатика) идут в общий пул. Привязка кабинета к классу НШ сама помечает общий (без предметов) кабинет как начальный, если уровень ещё не задан.

**Кабинеты только для подгрупп.** Флаг `subgroup_only` — маленькие комнаты: туда можно ставить только урок с номером группы. Целый класс (без `group_number`) туда нельзя — ни вручную, ни авто. Обычные кабинеты без флага принимают и класс, и подгруппы.

## Импорт Excel

Два типа файлов (шаблоны xlsx не выкладываем, пока не будет финального макета кабинетов).

### 1. Нагрузка по предмету (один файл = один предмет)

Школьный файл как `Инф.xlsx`:

| | Содержание |
|--|------------|
| Шапка | Предмет (B1 или имя листа), учебный год не импортируется |
| Строка заголовков | `№`, `ФИО`, классы (`1А`…`11Г`), `итого` (итого и № пропускаются) |
| Строки | Учителя и часы в неделю (пусто / 0 — не ведёт) |
| Имя предмета | Ячейка/лист, иначе имя файла, либо поле при загрузке одного файла |

Старый простой файл (первая строка: `Учитель`, `5А`…) тоже принимается.

Из файла создаются учителя, классы (уровень по номеру: 1–4 начальная, 5+ основная), предмет и назначения с часами.

- Два учителя с часами в одном классе → `group_number` 1 и 2
- Тот же ФИО в другом файле → тот же учитель, второе назначение

### 2. Кабинеты и предметы в них

Формат файла будет задан отдельно. До этого кабинеты можно заводить вручную.

### 3. Сетка расписания (обратный импорт отчёта)

Файл из «Отчёты»: полное расписание школы, класс или учитель. Уроки восстанавливаются по уже существующим назначениям (предмет + учитель + класс). Кабинеты подставляются по номеру. Не создаёт справочники — только ячейки сетки.

Существующие БД после обновления кода: `alembic upgrade head` (head — `18subject_group`). Ревизия `12classroom_subjects` переносит старый `classrooms.subject_id` в M2M; `13classroom_school_level` — тег уровня кабинета; `14subject_difficulty` — колонка `subjects.difficulty` (заменена в `18subject_group`); `15class_hour_lessons` — короче сетка в день классного часа; `17classroom_subgroup_only` — `classrooms.subgroup_only` (промежуточная `16requires_subgroup` на предмете снята).

## Роли

| Роль | Доступ |
|------|--------|
| `platform_admin` | `/admin` — школы и админы школ; без `school_id` не правит расписание |
| `school_admin` | всё приложение своей школы |

## Типовой сценарий (админ школы)

1. Импорт Excel (нагрузка по предметам) или ручное заполнение
2. Смены → привязка классов; кабинеты — вручную, пока нет второго файла
3. Сетка и/или автосоставление
4. Отчёты → Excel

## Стек

| Компонент | Технология |
|-----------|------------|
| Backend | Python 3.11+, FastAPI |
| ORM / миграции | SQLAlchemy, Alembic |
| БД | PostgreSQL (прод), SQLite (dev/тесты) |
| Auth | JWT (httpOnly cookie), argon2 |
| Frontend | React + Vite + TypeScript, TanStack Query, Bootstrap 5 |
| Автосоставление | OR-Tools CP-SAT; Celery + Redis на стенде |
| LLM (опционально) | Qwen / DashScope: формулировка «почему» и JSON-намерение assist; без ключа — шаблонный текст |
| Деплой | Docker Compose (nginx + api + Postgres; `--profile queue` — Redis + Celery) |

## Принципы

1. Простота первична — рабочий MVP, потом улучшения
2. Валидация везде
3. Юзабилити для завуча без длинной инструкции
4. Изоляция данных школ (`school_id`)

Продуктовые этапы 1–7 (CRUD, сетка, авто, React+FastAPI) закрыты. Следующая волна (Docker, auth, админка, очередь) — код готов, на сервере остаётся хост: [этапы выкладки](stages.md).
