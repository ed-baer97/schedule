# Продукт

Веб-сервис для составления и управления школьным расписанием: ручной и автоматический режимы, несколько школ на одной установке.

## Возможности

- Мультиарендность: платформенный админ создаёт школы и приглашает админов
- Вход по email/паролю (JWT в httpOnly cookie)
- Импорт из Excel: файл нагрузки на каждый предмет + файл кабинетов
- Справочники, нагрузка, назначения (в т.ч. подгруппы)
- Ручная сетка: drag & drop, валидация конфликтов
- Автосоставление: «Заполнить всё» — CP-SAT по смене; «по учителю» — лесенка; Repair — дозаполнение; на стенде Celery + Redis
- Отчёты в Excel

## Сущности

| Сущность | Описание |
|----------|----------|
| Школа | Тенант: изолированные справочники и расписание |
| Пользователь | `platform_admin` или `school_admin` |
| Учителя | ФИО, контакты, закреплённый кабинет (хозяин комнаты) |
| Кабинеты | Номер, название, корпус, вместимость; опционально предмет (`subject_id`) и флаг «фиксированный» (`is_exclusive`) |
| Классы | Название (1А, 5Б), уровень (НШ/ОШ), смена, классный руководитель, кабинет класса |
| Предметы | Название, цвет; флаг «нужен фиксированный кабинет» (пул комнат задаётся на кабинетах) |
| Назначения | предмет ↔ учитель ↔ класс, часы, подгруппа |
| Смены | уровень школы, сетка уроков, звонки |
| Задачи (jobs) | фон автосоставления (Celery) |

## Правила

**Подгруппы.** Два учителя с часами на один предмет в одном классе → подгруппы. В одну ячейку несколько предметов — только если они в группах.

**Несколько предметов у учителя.** Один и тот же учитель в нескольких файлах нагрузки (разные предметы) — ведёт несколько предметов.

**Структура.** Начальная / основная школа → смены → классы.

**Настройки.** На школу и уровень: дни, максимум уроков по предмету в день, режим кабинетов (`class_room` — учитель приходит к классу, `teacher_room` — дети к учителю). Для НШ — флаг «подгруппы уходят в кабинет учителя».

**Кабинеты и предметы.** Кабинет может быть привязан к предмету (пул: несколько лабораторий информатики). Фиксированный кабинет (`is_exclusive`) принимает только свой предмет. Предмет с флагом «нужен фиксированный кабинет» ставится только в кабинеты своего пула. Нефиксированный предметный кабинет (например 43-й математика) в авторасстановке заполняется по приоритету: хозяин комнаты → тот же предмет → общий кабинет → чужой нефиксированный. Если включено «подгруппы НШ уходят», групповой урок (не фиксированный предмет) ставится в домашний кабинет учителя — но только если этот кабинет разрешён предмету.

## Импорт Excel

Два типа файлов (шаблоны xlsx не выкладываем, пока не будет финального макета кабинетов).

### 1. Нагрузка по предмету (один файл = один предмет)

Школьный файл как `Инф.xlsx`:

| | Содержание |
|--|------------|
| Шапка | Предмет (B1 или имя листа), учебный год не импортируется |
| Строка заголовков | `№`, `ФИО`, классы (`1А`…`11Г`), `итого` (итого и № пропускаются) |
| Строки | Учителя и часы в неделю (пусто / 0 — не ведёт) |
| Имя предмета | Ячейка/лист, иначе имя файла, либо поле при загрузке одного файла |

Старый простой файл (первая строка: `Учитель`, `5А`…) тоже принимается.

Из файла создаются учителя, классы (уровень по номеру: 1–4 начальная, 5+ основная), предмет и назначения с часами.

- Два учителя с часами в одном классе → `group_number` 1 и 2
- Тот же ФИО в другом файле → тот же учитель, второе назначение

### 2. Кабинеты и предметы в них

Формат файла будет задан отдельно. До этого кабинеты можно заводить вручную.

## Роли

| Роль | Доступ |
|------|--------|
| `platform_admin` | `/admin` — школы и инвайты; без `school_id` не правит расписание |
| `school_admin` | всё приложение своей школы |

## Типовой сценарий (админ школы)

1. Импорт Excel (нагрузка по предметам) или ручное заполнение
2. Смены → привязка классов; кабинеты — вручную, пока нет второго файла
3. Сетка и/или автосоставление
4. Отчёты → Excel

## Стек

| Компонент | Технология |
|-----------|------------|
| Backend | Python 3.11+, FastAPI |
| ORM / миграции | SQLAlchemy, Alembic |
| БД | PostgreSQL (прод), SQLite (dev/тесты) |
| Auth | JWT (httpOnly cookie), argon2 |
| Frontend | React + Vite + TypeScript, TanStack Query, Bootstrap 5 |
| Автосоставление | OR-Tools CP-SAT; Celery + Redis на стенде |
| Деплой | Docker Compose |

## Принципы

1. Простота первична — рабочий MVP, потом улучшения
2. Валидация везде
3. Юзабилити для завуча без длинной инструкции
4. Изоляция данных школ (`school_id`)

Продуктовые этапы 1–7 (CRUD, сетка, авто, React+FastAPI) закрыты. Следующая волна (Docker, auth, админка, очередь) — код готов, на сервере остаётся хост: [этапы выкладки](stages.md).
